ШАГ 4. КАК ПОКАЗАТЬ CoR КАК KPI (в таблице)
---------------------------------------------------------------------
KPI в таблице = отдельная строка + свой формат + своё отклонение + цвет.

Добавь блок под Non-life (напр. строки 21-23):
  C21 SII_OFM_NL_COR_DISC     E21 CoR (IFRS 17 - discounted)
  C22 SII_OFM_NL_COR_UNDISC   E22 CoR (IFRS 17 - undiscounted)
  C23 (без кода)              E23 Discounting benefit (p.p.)

Формулы:
  F21, F22: та же SOMMA.PIÙ.SE, что в шаге 2
  F23:      =F22-F21       (сколько CoR "улучшает" дисконтирование)

Формат:
  Сначала посмотри, как хранится Value для CoR в 7.4 Data Export:
   ~0,93   -> формат Percentuale, 1 знак -> 93,0%
   ~93     -> уже в процентах -> формат 0,0"%"
   ~930    -> что-то иное (промилле?) -> уточнить у коллеги
  (на фото видно 906,92 / 920,1 / 932,46 - колонка обрезана, проверь в ячейке)

Отклонение для CoR - в п.п., НЕ в %:
  L21 = H21-G21       формат 0,0 "p.p." (если CoR в долях: =(H21-G21)*100)
  "CoR ухудшился на 2 п.п." - так говорят; "+2,2%" от 93% - путает.

Цвет (Formattazione condizionale -> Nuova regola -> Usa una formula):
  на F21:H22:
   =F21<1   -> зелёный  (CoR < 100% = андеррайтинговая прибыль)
   =F21>=1  -> красный
   (если CoR хранится как 93, а не 0,93 -> порог 100)
  на L21:L22:
   =L21>0   -> красный  (CoR вырос = хуже)
   =L21<0   -> зелёный
  !! для CoR логика обратная: рост = плохо. Для VNP рост = хорошо.

То же для Life - NBV margin:
  C25 (без кода)  E25 NBV margin (VNP / PVNBP)
  F25: =SE.ERRORE(F8/F16;"")     формат %
  L25: =H25-G25                  в п.п.; рост = хорошо (зелёный)
